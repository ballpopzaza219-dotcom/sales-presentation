# เช็คลิสต์สำหรับฝ่ายบัญชี — ยืนยันก่อนใช้งานจริง

จุดประสงค์: รวบรวมทุกจุดที่ระบบ (โมดูลเงินสดย่อย/เงินทดรองจ่าย/จ่ายเจ้าหนี้ภายนอก, หัวข้อ 1) ใช้สมมติฐาน
ด้านบัญชี/ภาษีที่**เขียนโดยไม่ใช่นักบัญชี** ต้องให้ฝ่ายบัญชียืนยันความถูกต้องก่อนเปิดใช้งานกับเงินจริง
รายการที่ยังไม่ผ่านการยืนยัน **ทุกจุดในไฟล์นี้ถือว่ายังไม่ผ่านการยืนยันจากฝ่ายบัญชี** — โค้ดใช้งานได้
จริงตามที่เขียน แต่ความถูกต้องเชิงบัญชี/ภาษียังไม่มีใครที่มีความรู้บัญชีมายืนยัน
อัปเดตล่าสุด: 2026-08-06

---

## 1. อัตราภาษีหัก ณ ที่จ่าย (WHT) ทั้ง 8 ประเภท

ตาราง `client_wht_income_types` (master, ใช้ร่วมกันทุกบริษัท เพราะอิงตามกฎหมาย ไม่ใช่ config รายบริษัท):

| code | รายละเอียด | อัตรา default |
|---|---|---|
| `40_1` | เงินเดือน ค่าจ้างแรงงาน (มาตรา 40(1)) | **NULL — คำนวณตามอัตราก้าวหน้า ไม่ใช่อัตราคงที่** ระบบยังไม่รองรับการคำนวณอัตราก้าวหน้า ถ้าถูกใช้จะ throw error (ตั้งใจ ป้องกันหักผิดอัตรา) |
| `40_2` | ค่านายหน้า ค่าธรรมเนียม (มาตรา 40(2)) | 3% |
| `40_3` | ค่าแห่งลิขสิทธิ์ (มาตรา 40(3)) | 3% |
| `40_4` | ดอกเบี้ย/เงินปันผล (มาตรา 40(4)) | 10% |
| `40_5` | ค่าเช่าทรัพย์สิน (มาตรา 40(5)) | 5% |
| `40_6` | ค่าวิชาชีพอิสระ (มาตรา 40(6)) | 3% |
| `40_7` | ค่าจ้างทำของ/รับเหมาก่อสร้าง (มาตรา 40(7)) | 3% |
| `40_8` | อื่นๆ ตามคำสั่งกรมสรรพากร ทป.4/2528 (มาตรา 40(8)) | 3% |

**ขอให้ยืนยัน**:
- [ ] อัตรา default ทั้ง 7 ประเภท (ไม่รวม 40_1) ถูกต้องตามกฎหมายปัจจุบัน ณ วันที่เริ่มใช้งานจริง
- [ ] `whtRate` ที่ผู้ใช้กรอกเองตอนสร้างเอกสาร (ระบบไม่บังคับให้ตรงกับ default เป๊ะ —ยอมให้ override
      ได้) เป็นพฤติกรรมที่ต้องการจริงหรือควรบังคับให้ตรงกับ master เท่านั้น
- [ ] ค่าจ้างทำของ/รับเหมาก่อสร้าง (40_7) ที่ผูกกับโมดูลนี้มากที่สุด (จ่ายผู้รับเหมา/supplier) อัตรา 3%
      ครอบคลุมทุกกรณีที่บริษัทใช้จริงหรือไม่ (เช่น ผู้รับเหมาบุคคลธรรมดา vs นิติบุคคล อัตราต่างกันหรือไม่)

## 2. รหัสผังบัญชีใหม่ 5 รหัส (เพิ่มเข้าทุกบริษัทอัตโนมัติ)

| รหัส | ชื่อบัญชี | ประเภท | ใช้ในโมดูล |
|---|---|---|---|
| `1110` | เงินสดย่อย | สินทรัพย์ | 1.1 |
| `1150` | ลูกหนี้เงินทดรองจ่าย | สินทรัพย์ | 1.2/1.3 |
| `1170` | ภาษีซื้อ | สินทรัพย์ | 1.3/1.4 |
| `2110` | เจ้าหนี้พนักงาน | หนี้สิน | 1.3 (กรณีสำรองจ่ายเกินวงเงิน) |
| `2120` | ภาษีหัก ณ ที่จ่ายค้างนำส่ง | หนี้สิน | 1.3/1.4 |

**ขอให้ยืนยัน**:
- [ ] ชื่อบัญชีและหมวดหมู่ (asset/liability) ถูกต้องตามผังบัญชีมาตรฐานที่บริษัทใช้จริง
- [ ] เลขรหัส (1110/1150/1170/2110/2120) ไม่ชนกับผังบัญชีเดิมที่บริษัทมีอยู่แล้วก่อนระบบนี้ และเข้ากับ
      ลำดับหมวดหมู่เดิมที่ใช้อยู่ (เช่น ช่วง 11xx = สินทรัพย์หมุนเวียนกลุ่มไหน)
- [ ] `2110 เจ้าหนี้พนักงาน` ไม่ซ้ำซ้อนความหมายกับบัญชีเจ้าหนี้อื่นที่มีอยู่แล้วในผังบัญชีเดิม (ตรวจสอบ
      ไปแล้วระดับ schema ว่าไม่ชนชื่อ/รหัส แต่ไม่ได้ตรวจสอบระดับนโยบายบัญชีว่าบริษัทมีบัญชี "เจ้าหนี้
      พนักงาน" อยู่แล้วในชื่ออื่นหรือไม่)

## 3. ผังบัญชี Dr/Cr — 5 เคสจากโมดูล 1.3 (เคลียร์เงินทดรองจ่าย)

สมมติฐานหลัก: **`Cr 1150` เท่ากับ `LEAST(advance_amount, total_expense_amount)` เสมอ** (ไม่มีทาง Cr
เกินยอดที่ลูกหนี้ค้างอยู่จริง) ส่วนต่างเกินวงเงินสำรองจ่ายจะไปเข้าเจ้าหนี้พนักงาน (2110) แทน ไม่ใช่ถือว่า
เงินสดจ่ายออกไปแล้วทันที

### เคส 1 — เบิกพอดี ไม่มี VAT ไม่มี WHT (advance=10,000, expense=10,000)
```
Dr ค่าใช้จ่าย (ตามบัญชีที่เลือก)   10,000
   Cr 1150 ลูกหนี้เงินทดรองจ่าย            10,000
```
สถานะ: `settled` ทันที (เบิกพอดี ไม่มีส่วนต่างต้องรอ)

### เคส 2 — เบิกเกิน มี VAT มี WHT (advance=10,000, expense=10,700 รวม VAT 700, WHT หัก 300)
```
Dr ค่าใช้จ่าย                       10,000
Dr 1170 ภาษีซื้อ                        700
   Cr 2120 ภาษีหัก ณ ที่จ่ายค้างนำส่ง            300
   Cr 1150 ลูกหนี้เงินทดรองจ่าย            10,000  (= LEAST(10,000, 10,700))
   Cr 2110 เจ้าหนี้พนักงาน                    400  (= 10,700 - 10,000 ส่วนเกินวงเงิน)
```
สถานะ: `approved` (ยังไม่ settled — ต้องรอจ่ายส่วนต่าง 400 ให้พนักงานผ่าน `/settle`)

### เคส 3 — เบิกขาด ไม่มี VAT/WHT (advance=10,000, expense=7,000)
```
Dr ค่าใช้จ่าย                        7,000
   Cr 1150 ลูกหนี้เงินทดรองจ่าย             7,000  (= LEAST(10,000, 7,000))
```
เหลือ Dr balance ค้างใน 1150 อีก 3,000 — สถานะ `approved` รอพนักงานคืนเงินส่วนที่เหลือผ่าน `/settle`
(settle ฝั่งนี้คือ "รับเงินคืนจากพนักงาน" ไม่ใช่ "จ่ายเงินเพิ่มให้พนักงาน" เหมือนเคส 2)

### เคส 4 — มี VAT แต่ `has_tax_invoice=false` (ไม่มีใบกำกับภาษี)
```
Dr ค่าใช้จ่าย                       (เต็มจำนวนรวม VAT ที่จ่ายจริง ไม่แยก 1170)
   Cr 1150 / 2110 ตามเคสข้างต้น
```
ไม่มีบรรทัด `Dr 1170` เลย แม้ `vat_amount > 0` — เหตุผล: ไม่มีใบกำกับภาษีเต็มรูป นำมาเป็นภาษีซื้อขอคืน
ไม่ได้ตามกฎหมาย จึงรวม VAT เข้าเป็นต้นทุนค่าใช้จ่ายทั้งก้อนแทน (DB มี CHECK บังคับว่า `has_tax_invoice
=false` ต้องคู่กับ `vat_amount=0` เท่านั้น — กรณีนี้จะเกิดได้เฉพาะตอนกรอก `vat_amount=0` พร้อมกับ
`has_tax_invoice=false` แต่โค้ดชั้น application ก็เช็คซ้ำอีกชั้นไม่พึ่ง DB CHECK อย่างเดียว)

### เคส 5 — ไม่มี WHT เพราะผู้รับเงินเป็นบุคคลที่ไม่ต้องหัก (เช่น ซื้อของจากร้านค้าทั่วไป)
```
Dr ค่าใช้จ่าย + Dr 1170 (ถ้ามีใบกำกับภาษี)
   Cr 1150 / 2110 ตามยอด
```
ไม่มีบรรทัด `Cr 2120` เลย — ระบบไม่บังคับหัก WHT เสมอ ขึ้นกับผู้ใช้กรอก `whtRate`/`whtIncomeTypeCode`
เองว่ามีหรือไม่

**ขอให้ยืนยัน**:
- [ ] โมเดล `Cr 1150 = LEAST(advance, expense)` + ส่วนต่างเข้า `2110`/ค้าง Dr ที่ 1150 ถูกต้องตามหลัก
      บัญชีจริง (ไม่ใช่แค่ debit=credit balance — ต้องยืนยันว่า "ความหมาย" ของบัญชีที่เลือกถูกต้อง)
- [ ] เคส 4 (ไม่มีใบกำกับภาษี → VAT รวมเป็นต้นทุน ไม่ขึ้น 1170) ถูกต้องตามนโยบายบัญชีของบริษัท
- [ ] **สมมติฐานกลไก WHT ที่ยังไม่เคยยืนยันกับฝ่ายบัญชีมาก่อน**: ระบบสมมติว่า "พนักงานจ่ายเงินให้ผู้รับ
      เงินปลายทางเป็นยอดสุทธิ (net) เท่านั้น ไม่เคยหักเงินสดจากพนักงานเอง" — บริษัทบันทึกภาระหัก ณ
      ที่จ่าย (2120) เป็นหนี้สินใหม่ที่**ไม่เกี่ยวกับกระแสเงินสดของพนักงานเลย** พนักงานไม่ต้อง "สำรอง"
      เงินภาษีส่วนนี้ล่วงหน้าเอง — ต้องยืนยันว่านี่คือกระบวนการจริงของบริษัท (ไม่ใช่กรณีที่พนักงานจ่าย
      เต็มจำนวนรวม WHT ไปก่อนแล้วบริษัทค่อยชดเชยคืนทีหลัง ซึ่งจะต้องบันทึกบัญชีคนละแบบ)

## 4. เงื่อนไขภาษีซื้อ (VAT) กรณีพนักงานสำรองจ่าย

**Gate ที่ใช้ในโค้ด**: `Dr 1170 ภาษีซื้อ` เกิดขึ้น**ก็ต่อเมื่อ** `has_tax_invoice = true AND
vat_amount > 0` เท่านั้น — เช็คซ้ำที่ชั้น application (ไม่พึ่ง DB CHECK อย่างเดียว) เหตุผลที่เช็คซ้ำ:
พบจากรีวิวว่าถ้าพึ่ง DB CHECK เพียงอย่างเดียวแล้วมีบั๊กอื่นทำให้สถานะข้อมูลผิดปกติ (ซึ่งไม่ควรเกิดได้ใน
เงื่อนไขปกติ) การคำนวณอาจพลาดขึ้นบรรทัด 1170 ทั้งที่ไม่มีใบกำกับภาษีจริง

**ขอให้ยืนยัน**:
- [ ] เงื่อนไข "มีใบกำกับภาษีเต็มรูป (`has_tax_invoice=true`)" เพียงพอสำหรับนำ VAT มาเป็นภาษีซื้อขอคืน
      ได้ หรือมีเงื่อนไขอื่นเพิ่มเติมที่ระบบยังไม่ได้ตรวจ (เช่น ชื่อ/เลขผู้เสียภาษีบนใบกำกับต้องตรงกับ
      บริษัทผู้ซื้อ, ประเภทสินค้า/บริการที่ VAT ขอคืนไม่ได้ตามกฎหมายบางประเภท)
- [ ] กรณีพนักงานสำรองจ่ายแล้วได้ใบกำกับภาษีแบบย่อ (ไม่ใช่เต็มรูป) ควรถือเป็น `has_tax_invoice=false`
      (VAT รวมเป็นต้นทุน) ตามที่ระบบทำอยู่ หรือมีข้อยกเว้นอื่น

## สรุปวิธีใช้เช็คลิสต์นี้

ทุกช่องที่ยังไม่ติ๊ก = ยังไม่ผ่านการยืนยันจากฝ่ายบัญชี โค้ดทำงานตามที่อธิบายไว้จริง (ทดสอบผ่าน HTTP จริง
แล้วทุกเคส รวมยอด debit=credit ทุกรายการ) แต่ **ความถูกต้องเชิงบัญชี/ภาษียังต้องให้ผู้มีความรู้บัญชี
ยืนยันก่อนใช้กับเงินจริง** โดยเฉพาะข้อ 3 (สมมติฐานกลไก WHT) และข้อ 1 (มาตรา 40_7 ที่ใช้บ่อยที่สุดใน
โมดูลนี้)
