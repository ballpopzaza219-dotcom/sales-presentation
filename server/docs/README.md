# SiteReq — สารบัญเอกสาร + สถานะโปรเจกต์

หน้ารวมสำหรับคนที่มารับงานต่อ (หรือเจ้าของโปรเจกต์เองอีกหลายเดือนข้างหน้า) ให้เริ่มงานได้เร็วโดยไม่ต้อง
ไล่อ่านทุกไฟล์ — อัปเดตล่าสุด: 2026-08-27

---

## ระบบทำอะไรได้บ้างตอนนี้ (สรุปแบบไม่ต้องอ่านโค้ด)

SiteReq คือระบบบริหารงานก่อสร้างสำหรับบริษัทรับเหมา ครอบคลุมทั้งฝั่ง **จ่ายเงินออก** และ **เรียกเก็บเงินเข้า**
ของโครงการหนึ่งๆ ทุกธุรกรรมที่มีเงินเกี่ยวข้องจะถูกบันทึกลงบัญชีคู่ (double-entry) ให้อัตโนมัติ พร้อมมี
ขั้นตอนขอ-ตรวจ-อนุมัติ (workflow) และ log ว่าใครทำอะไรเมื่อไหร่ เพื่อให้ตรวจสอบย้อนหลังได้ครบ

**ฝั่งจ่ายเงินออก:**
- **ขอซื้อของ (ใบขอซื้อ / PR)** — พนักงานหน้างานขอซื้อวัสดุ/อุปกรณ์ อ้างอิงงบประมาณโครงการ (BOQ) ได้ว่า
  แต่ละบรรทัดเหลืองบเท่าไหร่ ผ่านขั้นตอนขออนุมัติตามวงเงินที่ตั้งไว้
- **สั่งซื้อ/สั่งจ้าง (PO/WO)** — ออกใบสั่งซื้อวัสดุจากผู้ขาย (PO) หรือทำสัญญาว่าจ้างผู้รับเหมาช่วง (WO)
  พร้อมขั้นตอนอนุมัติ ผูกกับงบประมาณโครงการ
- **ตรวจรับของตาม PO** — คนหน้างานบันทึกว่าของที่สั่งมาถึงจริงกี่ชิ้น ทยอยรับหลายครั้งต่อ PO ใบเดียวได้
  (partial receipt) แนบรูปใบส่งของได้ ระบบกันรับของเกินยอดสั่งอัตโนมัติ และบล็อกไม่ให้ยกเลิก PO ที่รับของ
  ไปแล้ว
- **เงินสดย่อย / เงินทดรองจ่าย** — เบิกเงินสดย่อยไปใช้จ่ายเล็กๆ น้อยๆ หรือให้พนักงานเบิกเงินล่วงหน้าไปสำรอง
  จ่ายแทนบริษัทก่อน แล้วมาเคลียร์บิลทีหลัง (พร้อมคำนวณภาษีหัก ณ ที่จ่ายและออกหนังสือรับรอง 50 ทวิให้อัตโนมัติ
  ถ้ามี)
- **ส่งบิลค่าใช้จ่ายจากหน้างาน** — คนหน้างานที่ซื้อของ/จ่ายเงินเองก่อน ส่งรูปบิล+ยอดเงิน+ที่มาของเงิน (เบิก
  เงินสดย่อยไปก่อน / ออกเงินเองไปก่อน / ซื้อเชื่อ) เข้าคิวรอฝ่ายบัญชีตรวจแล้วสร้างเอกสารจริง (ใบเคลียร์เงิน
  ทดรองจ่าย หรือใบเบิกจ่ายเจ้าหนี้ภายนอก) เอง ไม่ auto-convert — มีปุ่มดึงข้อมูลที่กรอกไว้ไปเติมในฟอร์มสร้าง
  เอกสารให้อัตโนมัติเพื่อลดการพิมพ์ซ้ำ
- **จ่ายเจ้าหนี้ภายนอก** — จ่ายเงินให้ผู้รับเงินภายนอกโดยตรง (ไม่ผ่านพนักงานสำรองจ่าย) พร้อมภาษีซื้อ/ภาษีหัก
  ณ ที่จ่ายเหมือนกัน
- **เบิกเงินตามสัญญาจ้างผู้รับเหมาช่วง** — จ่ายเงินล่วงหน้าให้ผู้รับเหมาช่วงตอนเริ่มงาน, เบิกจ่ายตามงวดงานที่
  ทำเสร็จ (หักคืนเงินล่วงหน้า + กันเงินประกันผลงานอัตโนมัติตาม % ที่ตกลงในสัญญา), และคืนเงินประกันผลงานตอน
  จบงาน — กันไม่ให้เบิกเกินมูลค่าสัญญาหรือคืนเงินประกันผลงานเกินยอดที่กันไว้

**ฝั่งเรียกเก็บเงินเข้า:**
- **บันทึกความคืบหน้าโครงการ (Progress Claims)** — เรียกเก็บเงินจากเจ้าของโครงการตามงวดงาน (อิงงวดที่ตกลง
  ไว้ หรืออิง % ความคืบหน้าจริงเทียบกับ BOQ), เรียกเก็บเงินล่วงหน้า, ผ่านขั้นตอนตรวจสอบผลงานก่อนอนุมัติ
  (certify แล้วค่อย approve — แยกคนละคนกันเสมอ) ระบบจะหักเงินล่วงหน้าที่เคยรับไปแล้วออกจากยอดที่เรียกเก็บ
  งวดถัดไปให้อัตโนมัติ (FIFO)

**ส่วนกลางที่ใช้ร่วมกันทุกโมดูล:**
- **2 มุมมองของงานเดียวกัน — โมดูล "จัดซื้อวัสดุ (PR)" กับโมดูล "บัญชี-การเงิน (Finance)"** — เอกสารที่
  เกี่ยวกับงานปฏิบัติการ (PR, PO, WO, เบิกเงินผู้รับเหมาช่วง, ตรวจรับของ, ส่งบิลหน้างาน, บันทึกความคืบหน้า
  โครงการ, เงินสดย่อย/เงินทดรองจ่าย) เห็นได้จากทั้ง 2 โมดูล — คนหน้างาน/จัดซื้อใช้ผ่านโมดูล PR (ไม่ต้องเข้า
  Finance เลย) ส่วนฝ่ายบัญชีใช้ผ่านโมดูล Finance ที่มีเครื่องมือปิดงวด/งบการเงินเพิ่มเติม (สมุดรายวัน, งบ
  ทดลอง, งบกำไรขาดทุน, งบดุล ฯลฯ) ที่ไม่โผล่ในโมดูล PR เป็นข้อมูลชุดเดียวกัน หน้าเดียวกันทั้งสองทาง ไม่ได้
  ทำซ้ำสองชุด — ใครเห็นเมนูไหนคุมด้วย permission flag เดียวกันทั้งสองฝั่งเสมอ
- **สิทธิ์การอนุมัติแบบละเอียด** — กำหนดได้ว่าใครอนุมัติเอกสารประเภทไหนได้ในวงเงินเท่าไหร่ แยกจากสิทธิ์
  "จัดการ/ตั้งค่า" เสมอ (เช่น คนตั้งเพดานวงเงินกองทุน ไม่ใช่คนเดียวกับคนอนุมัติการเบิกจากกองทุนนั้น) ห้าม
  อนุมัติเอกสารที่ตัวเองเป็นคนสร้าง/ยื่นเสมอ — คนหน้างานที่ไม่มีสิทธิ์เข้า Finance เลยก็ยังตรวจรับของ/ส่งบิล
  ได้ผ่าน flag เฉพาะของตัวเอง (`can_submit_goods_receipt`, `can_submit_site_expense`)
- **บัญชีแยกประเภท (Journal/Ledger)** — ทุกธุรกรรมเงินโพสต์บัญชีคู่ (debit=credit เสมอ) อัตโนมัติทันทีที่
  อนุมัติ ตรวจสอบย้อนกลับไปยังเอกสารต้นทางได้เสมอว่ารายการนี้มาจากเอกสารใบไหน
- **หนังสือรับรองหัก ณ ที่จ่าย (50 ทวิ)** — ออกให้อัตโนมัติทุกจุดที่มีการหักภาษี ณ ที่จ่ายจริง พร้อมสรุปยอด
  รายเดือนให้ฝ่ายบัญชีเอาไปยื่นภาษีเอง (ระบบยังไม่ได้ปิดยอดในบัญชีให้อัตโนมัติตอนนำส่งจริง — ดู known
  limitations)
- **ไฟล์แนบ (รูปใบส่งของ/บิล)** — อัปโหลดได้หลายไฟล์ต่อเอกสาร (jpg/png/webp/pdf, 5MB/ไฟล์) เก็บบนดิสก์
  เครื่อง server จริง ดูได้เฉพาะคนในบริษัทเดียวกันที่ login อยู่เท่านั้น (บังคับที่ server ไม่ใช่แค่ซ่อนลิงก์)

**ยังไม่มี / ยังไม่ชัดเจน**: การปิดโครงการแบบอสังหาริมทรัพย์ (โอนกรรมสิทธิ์/ผ่อนดาวน์) — ดูหัวข้อ 3.2 ใน
[`pr-module-known-limitations.md`](./pr-module-known-limitations.md)

## โครงสร้างระบบ

```
Internet ──▶ build-con.com ──▶ Cloudflare Tunnel ("build-con", remotely-managed)
                                        │
                                        ▼
                              localhost:3000 (Windows Service "SiteReqServer" ผ่าน NSSM)
                                        │
                                        ▼
                              server/server.js (Express)
                                        │
                                        ▼
                              PostgreSQL 18 (Windows Service "postgresql-x64-18")
                              database: sitereq_db
                              app เชื่อมต่อด้วย role sitereq_app (ไม่ใช่ superuser)
```

- **Frontend**: `pr-system.html` (แอปหลักที่ลูกค้าใช้ — vanilla JS SPA ไม่มี build step) +
  `admin-panel.html` (แผงควบคุมฝั่ง platform admin) — locale ที่ `locales/th.json`/`locales/en.json`
  — การเปลี่ยนหน้า/เปิดฟอร์มทุกจุดต้องผ่าน `goToPage()` เท่านั้น (จุดรวมที่เรียก loader ที่หน้านั้นต้องใช้
  ให้อัตโนมัติ — ดู CLAUDE.md หมวด "กฎการเขียน frontend")
- **Backend**: `server/server.js` ไฟล์เดียว (Express + `pg`) — ไม่มี framework แบ่ง route หลายไฟล์
- **ไฟล์แนบ**: เก็บบนดิสก์จริงที่ `server/uploads/<ชื่อฟีเจอร์>/` (สุ่มชื่อไฟล์กันชนกัน) ไม่ผ่าน
  `express.static` เลย (มี guard บล็อก `/server/*` ทั้งหมดไว้แล้ว) — เข้าถึงได้เฉพาะผ่าน endpoint ที่เช็ค
  login + company scope ทุกครั้ง ไม่มีเอกสารไหนอนุญาตดาวน์โหลดแบบไม่ต้อง login เลย
- **Migration**: `server/migrations/000N_*.up.sql`/`.down.sql` — รันผ่าน `node migrations/migrate.js up`
  (ดู `server/migrations/migrate.js` — มี advisory lock กันรันซ้อน, track ใน `schema_migrations`)
- **Test**: `server/tests/*.regression.js` — ยิง HTTP จริงใส่ server ที่ต้องรันอยู่ก่อน (`localhost:3000`)
  ใช้ fixture ร่วมจาก `server/tests/fixtures/setup-approval-fixtures.js` (idempotent, รันซ้ำได้)
  รันทั้งชุดได้ด้วย `npm run test:regression-all` — ดู `server/package.json` สำหรับรันทีละไฟล์

## Setup เครื่องใหม่ตั้งแต่ต้นจนจบ

**1) PostgreSQL 18** — ติดตั้ง แล้วสร้าง role/database (หรือ restore จาก backup — ถ้ามี `pg_dumpall`
ให้ import ด้วย `psql` ระวังเรื่อง encoding บน Windows: ต้อง
`psql ... -c "SET client_encoding TO 'UTF8';" -f dump.sql` เสมอ ไม่งั้นคอมเมนต์/ข้อมูลภาษาไทยจะพัง)

**2) Clone repo** (private — ต้องมีสิทธิ์เข้าถึง):
```cmd
git clone https://github.com/ballpopzaza219-dotcom/sales-presentation.git
```

**3) ตั้งค่า `.env`**:
```cmd
copy server\.env.example server\.env
```
แก้ `server/.env` ใส่ค่าจริง (`PGPASSWORD`, `SESSION_SECRET` สุ่มใหม่ด้วย `crypto.randomBytes(32)`,
`GMAIL_USER`/`GMAIL_APP_PASSWORD` ถ้าต้องการส่งอีเมล, `APP_BASE_URL=https://build-con.com`)

**4) ติดตั้ง Node.js** (ถ้ายังไม่มี): `winget install OpenJS.NodeJS.LTS`

**5) ติดตั้ง dependencies + รัน migration**:
```cmd
cd server
npm install
node migrations\migrate.js up
node migrations\migrate.js status
```
ต้องเห็น migration ทุกตัวขึ้น `[x]` ครบ (ปัจจุบันมีถึง 0018)

**6) ทดสอบรันตรงก่อน** (ยังไม่ตั้ง service):
```cmd
npm start
```
เปิด `http://localhost:3000` ต้องเห็นหน้า login

**7) ตั้งเป็น Windows Service** — ดู [`nssm-service-setup.md`](./nssm-service-setup.md) เต็มๆ (ต้อง
Administrator, ต้องตั้ง `DependOnService postgresql-x64-18` ด้วยเสมอ)

**8) เปิดให้เข้าจากภายนอก** — ดู [`cloudflared-tunnel-setup.md`](./cloudflared-tunnel-setup.md) เต็มๆ
(สร้าง tunnel ผ่าน **dashboard เท่านั้น** อย่าใช้ `cloudflared tunnel create` ผ่าน CLI — จะได้ tunnel แบบ
locally-managed ที่แก้ route จาก dashboard ไม่ได้อีกเลย เจอปัญหานี้มาแล้วจริงกับ tunnel เดิม
`sitereq-tunnel`)

**9) ตรวจสอบทั้งระบบ** — รัน `server\scripts\health-check.ps1` เช็ค service/URL ทั้งหมด แล้วรัน
`npm run test:regression-all` ใน `server/` (ต้องมี server รันอยู่ก่อน ผ่าน `npm start` หรือ service ก็ได้)
ต้องผ่านครบทุกไฟล์
